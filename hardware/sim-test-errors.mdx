---
title: Fix a SIM test error
description: What each error message in a SIM test result means (USSD, SMS, calls, data, network technology) and what to do about it.
---

A SIM can look healthy and still fail a test. Look up the error message on this page: each one has its own row saying what it means and what to do. If the SIM itself looks wrong in the platform, start with [Troubleshoot a SIM](/hardware/sim-troubleshooting) instead.

The messages below are the ones the platform shows in the test result, word for word. Any other text is the network's own answer: a menu, a balance, or a gateway error such as `USSDC: ESME fault.` or `Service not available`. The robot and the platform did their job, so the problem lies with the line or the service being called. Hand the text to the team that runs that service.

Start by [rebooting the slot](/hardware/sim-troubleshooting#where-to-start).

## USSD

| Message | What it means | What to do |
|---|---|---|
| `Connection problem or invalid MMI code (+CME ERROR: 100)` | The network rejected the request. | If several SIMs fail at the same time, the USSD platform is the cause: replay the shortcode on another SIM of the site in a [live session](/tests/live-session) to confirm.<br /><br />If only one SIM is affected, reboot its slot. If the problem persists, test the card in a phone. |
| `Connection problem or invalid MMI code (+CME ERROR: 258)` | The SIM refuses USSD requests. | Reboot the slot, then have your network team check the line's profile. |
| `No network service (+CME ERROR: 30)` | No network service was available to the SIM when the request was sent. | Check the SIM's **Network** column.<br /><br />If the SIM is registered, the cause is on the network side. If it isn't, follow [Troubleshoot a SIM](/hardware/sim-troubleshooting). |
| `Call barred (+CME ERROR: 257)` | USSD is barred on the line. | Lift the barring. |
| `Network Timeout (+CUSD 5)`<br /><br />`no ussd response received from network`<br /><br />`Ussd session closed by operator (+CUSD:2)` | The network didn't answer, or closed the session early: poor coverage, an expired USSD licence, or an overloaded USSD server. | Give the team that runs your USSD platform the code, the time, and the SIM's number. |
| `Wrong USSD code format` | The code set in the test isn't shaped like a USSD code. | Correct the **Command** field of the test. |

## SMS

| Message | What it means | What to do |
|---|---|---|
| `SMS not received.` | The expected SMS didn't reach the SIM in time. | The monitor waits for the SMS as long as its **SMS timeout** allows, in the monitor's **Options** section. If that's too short for your service, you can raise it.<br /><br />Test the card in a phone. If it receives nothing there either, check the line and the SMSC.<br /><br />Every SMS test of one robot failing usually means the robot's clock has drifted: write to support@kapptivate.com with the robot's name as the platform shows it. |
| `failed to send sms` | The SIM couldn't send the SMS. | Check the line's credit, then its SMSC. |

## Calls

Whatever the call error, listen to the calling side's recording first: in the result, open the **Artifacts** section of the **Place Call** step and download the `record-place-…` file. Artifacts are kept for 24 hours. The recording sometimes settles the question on its own: a line that's always busy, an announcement that the credit has run out, an odd tone.

| Message | What it means | What to do |
|---|---|---|
| `cannot place call to <NUMBER>` | The calling SIM couldn't place the call. | Check that it's registered and has credit.<br /><br />If the test forces the call over VoLTE, also check that VoLTE is provisioned on the line. |
| `call quit unexpectedly` | The called service answered, then dropped the call in under a second. The step ends before its planned duration and the recording is silent. | Check the failure times against the service's opening hours.<br /><br />Give the number called and those times to the team that runs the service. |
| `call was correctly emitted but was suddenly stopped` | The SIM has no airtime, or isn't allowed to call this number (short numbers, or roaming). | Check the line's credit and which numbers it may call. |
| `timeout call not pick up` | Nobody picked up on the receiving side. | Check that the called SIM is registered. |
| `call not ended correctly` | Receiving side, on **Wait Call**: the caller never hung up, so the step waited 4 minutes. | Reboot the calling SIM's slot.<br /><br />If the error comes back, or if its **Place Call** step succeeded, write to support@kapptivate.com with the link to the execution. |
| `timeout, an error occurred during call` | Calling side, on **Place Call**: the calling SIM stopped answering during the call. It comes with `call not ended correctly`. | Same fix as `call not ended correctly`: reboot the calling SIM's slot. |
| `timeout no call received` | The called SIM received no call. | Read the result of the calling side, and check the number it dials. |

## Data

| Message | What it means | What to do |
|---|---|---|
| `No internet after PDP activation` | The data bundle is used up or has expired. | Top up the line. |
| `Failed to activate PDP context (timeout while waiting cellular network attachment)` | The SIM isn't attached to the network. | Go back to [where to start](/hardware/sim-troubleshooting#where-to-start). |
| `Failed to activate PDP context (no 'APN' specified)` | The test has no APN to use. | Fill in **APN Name** in the test.<br /><br />Or turn **Use default APN credentials** back on, once the SIM has one: a SIM has no default APN until someone fills in **Default APN** in its **Settings** tab and clicks **Save changes**. |
| `Failed to activate PDP context (Unspecified reason)` | The data connection failed, and the network gave no reason. | Check the APN and the line's data subscription. |

## Network technology

The robot switches technology before it runs the action.

| Message | What it means | What to do |
|---|---|---|
| `failed to change network technology: sim not registered` | The SIM has no network at all, on any technology. | Go back to [where to start](/hardware/sim-troubleshooting#where-to-start).<br /><br />Set **Access technology** to **Default** on every step of every test this SIM runs, not only the failing one, then reboot the slot.<br /><br />If a test checks 3G or 2G on purpose, report the missing technology to your network team instead.<br /><br />Still failing? Write to support@kapptivate.com. |
| `failed to change network technology: timeout while waiting network registration` | The SIM has a network, just not on the technology the test asks for. | Set **Access technology** to **Default** on every step of every test this SIM runs, not only the failing one, then reboot the slot.<br /><br />If a test checks 3G or 2G on purpose, report the missing technology to your network team instead.<br /><br />Still failing? Write to support@kapptivate.com. |
| `failed to change network technology: ERROR` | The robot couldn't switch technology. | Set **Access technology** to **Default** on every step of every test this SIM runs, not only the failing one, then reboot the slot.<br /><br />If a test checks 3G or 2G on purpose, report the missing technology to your network team instead.<br /><br />Still failing? Write to support@kapptivate.com. |

## Robot and test

| Message | What it means | What to do |
|---|---|---|
| `Robot unreachable` | The robot is **Offline**, or the SIM is no longer detected in any robot. | If the robot is **Offline**, follow [Troubleshoot an Offline robot](/hardware/network-troubleshooting).<br /><br />If the robot is **Online**, the SIM is the one no longer detected: follow [Troubleshoot a SIM](/hardware/sim-troubleshooting). |
| `SIM timeout` | The slot didn't answer within the timeout, four minutes by default. | Reboot the slot.<br /><br />If it comes back, write to support@kapptivate.com. |
| `Owner <NUMBER> not recognized` | No SIM your product is allowed to use carries this number. The number can also show empty or in braces (`Owner {SIM} not recognized`). | Select an available device in the test, or for a monitor in **Edit monitor**, under **Device**.<br /><br />**Edit related test** doesn't change the monitor's device. |

## The answer isn't the expected one

When a USSD answer or an SMS doesn't match what the test expects, the step fails with no error message: it shows the expected answer next to the one received. Compare them. The service may have changed its wording, or answered with an error such as an empty balance.

## A failed assertion

An assertion is a condition you added to the test so that it fails when a measurement isn't good enough. When the condition isn't met, the test fails even though the SIM and the robot did their job.

The step's **Assertion** section lists every condition of the test. The one that failed it shows the measured value next to the expected condition, for example:

- `audio_mos (2.56) is not superior or equal to 2.6`
- `duration (4.82) is not strictly inferior to 3`
- `body doesn't contain MCO=OGC`

Investigate the quality of the service being measured. If the threshold no longer matches what you want to watch, adjust the assertion in the test.

## Any other message

A message that isn't on this page and doesn't read like a network answer comes from the platform or the robot. Write to support@kapptivate.com with the link to the failed execution and the exact message.
