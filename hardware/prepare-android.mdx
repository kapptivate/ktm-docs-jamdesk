---
title: Prepare an Android smartphone
description: Set up a Samsung phone so a robot can keep it awake, reach it over USB, and run mobile app tests on it.
---

A new Samsung ships set against exactly what a robot needs. It sleeps, it trims background apps on its own, it updates mid-run, and one security feature blocks USB commands outright. Turn those off in order and the phone ends up in its robot's device list, marked **Available**.

The paths below come from One UI 7, on Android 15. An earlier One UI groups the battery settings differently, and another Android brand puts the same settings under similar names, rarely in the same place.

<Note>
  [Samsung is the only fully supported Android brand](/questions/devices-os-versions). Other makers ship customized OS layers that can interfere with mobile automation, and investigations on those phones come out of your support package.
</Note>

## Before you start

- The robot is installed, with its USB hub powered on: see [install a robot](/hardware/install-robot).
- The robot shows **Online** in the platform: see [configure the robot network](/hardware/configure-network).
- The phone runs a [supported Android version](/questions/devices-os-versions) and has at least 4 GB of RAM.
- A USB-C to USB-A cable, preferably a new one. The hub's ports are USB-A, and the phone cables don't ship with the robot. A worn cable is enough to make the phone vanish from the platform, with no other symptom.

## First boot

Turn the phone on and go through the Android setup. Pick the language and country you want, then skip every account.

<Warning>
  Don't set a screen lock: no password, no PIN, no pattern. The screen has to stay unlocked for the platform to use the phone.
</Warning>

One screen in that setup decides whether the phone will ever work with Kapptivate. On **Samsung services**, Auto Blocker comes pre-ticked, and one of the four things it blocks is commands sent over the USB cable. That is how a robot drives a phone. Untick **Auto Blocker**, then tap **Agree**.

<Frame caption="The Samsung services screen, with Auto Blocker still ticked">
  ![The Samsung services setup screen, Auto Blocker ticked, listing Blocks commands by USB cable](/images/hardware/prepare-android-01.webp)
</Frame>

<Note>
  Already past that screen? Go to **Settings > Security and privacy > Auto Blocker** and turn it off there, before you set the developer options below.
</Note>

## Set up the phone

<Steps>
  <Step title="Make Chrome the default browser">
    In **Settings > Apps > Choose default apps > Browser app**, select **Chrome**. On Android 15 it is usually selected already. If Chrome isn't listed, install it from the Play Store first.
  </Step>
  <Step title="Unlock the developer options">
    In **Settings > About phone > Software information**, tap **Build number** repeatedly until Android confirms that developer mode is on. **Developer options** then appears near the bottom of the Settings list.
  </Step>
  <Step title="Set the developer options">
    In **Settings > Developer options**, set these six:

    | Setting | State |
    |---------|-------|
    | Stay awake | On |
    | Auto update system | Off |
    | USB debugging | On |
    | Disable adb authorization timeout | On |
    | Verify apps over USB | Off |
    | Verify bytecode of debuggable apps | Off |

    **USB debugging** is the one that makes the phone drivable over the cable at all. **Disable adb authorization timeout** keeps that authorization from expiring after seven idle days, so the phone stays reachable between campaigns.

    <Note>
      **Revoke USB debugging authorizations** sits in the same list, but it's an action, not a setting. Leave it alone. It clears every computer the phone already trusts, the robot included.
    </Note>
  </Step>
  <Step title="Stop Android from sleeping the apps">
    In **Settings > Battery > Background usage limits**, turn **Put unused apps to sleep** off. Samsung suspends apps it decides you no longer use, and a phone on a robot has to stay reachable between campaigns.

    On that same screen, open the menu at the top right, choose **Adaptive battery**, and turn it off. Nothing on the screen hints that it's in there.

    <Frame caption="The menu at the top right of Background usage limits, open">
      ![The Background usage limits screen with its top-right menu open on Adaptive battery](/images/hardware/prepare-android-02.webp)
    </Frame>
  </Step>
  <Step title="Turn off fast charging">
    In **Settings > Battery**, scroll down to **Charging settings** and turn **Fast charging** off. A phone bolted to a hub is never in a hurry to charge, and fast charging only adds heat.
  </Step>
  <Step title="Cap the charge">
    Still in **Settings > Battery**, open **Battery protection**, turn it on, select **Maximum**, and leave the slider on **80%**.

    A phone on the hub charges permanently, and [that is what makes smartphone batteries swell](/hardware/swap-battery#smartphone-batteries-swelling). **Maximum** stops charging at 80% instead of holding the cell at full. The durable fix is still a phone that supports pass-through charging.

    <Frame caption="Battery protection, on and set to Maximum at 80%">
      ![The Battery protection screen, switched on, with Maximum selected and the slider on 80%](/images/hardware/prepare-android-03.webp)
    </Frame>
  </Step>
  <Step title="Turn off automatic updates">
    In **Settings > Software update**, open **Auto download** and select **Never**. The platform supports [Android 8 to 16](/questions/devices-os-versions), and an update can push the phone past the versions it covers.

    <Note>
      The same screen warns that critical updates can still download on mobile data. **Never** narrows that risk, it doesn't remove it.
    </Note>
  </Step>
  <Step title="Connect the phone to the robot">
    Plug the phone into a free USB port of the hub. If it was already plugged in, unplug it and plug it back: the popup only fires on connection.

    On the phone, tick **Always allow from this computer**, then tap **Allow**. Without the tick, the authorization dies the next time the robot reconnects.

    <Frame caption="The Allow USB debugging? popup, with Always allow from this computer ticked">
      ![The USB debugging authorization popup, the Always allow from this computer box ticked](/images/hardware/prepare-android-04.webp)
    </Frame>
  </Step>
</Steps>

## Check that it worked

Open the Kapptivate platform and go to [**Agents**](/equipment/agents), where the platform lists your robots. Open yours: the phone appears in its device list and shows **Available** once it is ready to take tests.

A device only becomes available when its own status is **Available** and the robot carrying it is **Online**. If the phone shows nothing, look at the robot first.

If the phone never appears at all, unplug and replug the cable and watch for the authorization popup. A popup dismissed too fast is the usual cause, and it only comes back on reconnection. If it comes back and the phone still doesn't appear, Auto Blocker is the next thing to check, under **Settings > Security and privacy**.
