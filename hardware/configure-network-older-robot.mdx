---
title: Change the IP of an older robot
description: Give a robot with no desktop a new IP address, gateway, and DNS server, with a few commands typed on its console.
---

Older robots have no desktop, so you change their IP address from the console, with a few commands. Plan for the downtime: the robot runs no test from the moment you change its address until it reads **Online** again.

This page is for robots that drop you straight at a command line once you log in. See a Linux desktop instead? Follow [configure the robot network](/hardware/configure-network#set-the-static-ip).

## Before you start

- A screen and a keyboard. The screen plugs in over HDMI or VGA, depending on the model.
- The robot's credentials. Ask support@kapptivate.com if you don't have them.
- The new IP address, its mask, the gateway, and the DNS server, from your IT team.
- On a filtered corporate network, the flows opened for the new address. The IP requirements document lists them: ask support@kapptivate.com for it. Without those flows, the robot stays **Offline** on its new address.

## Log in

Plug the screen and the keyboard into the back of the robot, then type the user name and the password. Nothing shows while you type the password, and that's expected.

<Note>
  The robot expects an AZERTY keyboard, or a QWERTY one on some robots. Type `a` at the login prompt. If a `q` shows up, plug in a keyboard with the other layout.
</Note>

Whenever `sudo` asks for a password on this page, type the one you logged in with.

## Find the port

```bash
ip -br link | grep ^en
```

```
enp1s0           DOWN           00:00:5e:00:53:01 <BROADCAST,MULTICAST>
enp2s0           UP             00:00:5e:00:53:02 <BROADCAST,MULTICAST,UP,LOWER_UP>
```

The cable sits in the port that shows `UP` in the second column, `enp2s0` here. Write that name down.

No port shows `UP`? Move the cable to another port and run the command again. Several ports show `UP`? The robot is on more than one network, so stop here and write to support@kapptivate.com.

## Write the new address

List the robot's network files first.

```bash
ls /etc/netplan
```

If `50-cloud-init.yaml` is in the list, run this command. Skip it and the robot puts its old configuration back at every boot.

```bash
echo "network: {config: disabled}" | sudo tee /etc/cloud/cloud.cfg.d/99-disable-network-config.cfg
```

Then move the old configuration aside. It waits in `/etc/netplan-backup` in case you need to [go back to the old address](#go-back-to-the-old-address).

```bash
sudo mkdir -p /etc/netplan-backup
sudo mv /etc/netplan/*.yaml /etc/netplan-backup/
```

Now write the new configuration. Replace the values in capitals:

```bash
echo "network: {version: 2, ethernets: {PORT: {addresses: [ADDRESS/PREFIX], routes: [{to: 0.0.0.0/0, via: GATEWAY}], nameservers: {addresses: [DNS]}}}}" | sudo tee /etc/netplan/01-netcfg.yaml
```

- `PORT` is the port that showed `UP`, such as `enp2s0`.
- `ADDRESS/PREFIX` is the new IP address, a slash, then the short form of the mask from the table below, such as `192.168.10.42/24`.
- `GATEWAY` is the gateway address.
- `DNS` is the DNS server address. With two servers, separate them with a comma and a space.

| Mask | Short form |
|---|---|
| 255.255.0.0 | /16 |
| 255.255.240.0 | /20 |
| 255.255.252.0 | /22 |
| 255.255.254.0 | /23 |
| 255.255.255.0 | /24 |
| 255.255.255.128 | /25 |
| 255.255.255.192 | /26 |
| 255.255.255.224 | /27 |

For any other mask, ask your IT team for the short form.

Filled in for a robot at `192.168.10.42` on a `255.255.255.0` network, the command reads:

```bash
echo "network: {version: 2, ethernets: {enp2s0: {addresses: [192.168.10.42/24], routes: [{to: 0.0.0.0/0, via: 192.168.10.1}], nameservers: {addresses: [192.168.10.53]}}}}" | sudo tee /etc/netplan/01-netcfg.yaml
```

The robot prints the line back. That's the new content of the file.

## Check the file and reboot

Check the file.

```bash
sudo netplan generate
```

A valid file prints nothing, or this warning, which blocks nothing:

```
** (generate:1225): WARNING **: 15:24:04.849: Permissions for /etc/netplan/01-netcfg.yaml are too open. Netplan configuration should NOT be accessible by others.
```

An error means a typo in the line. Fix it before you reboot: with an invalid file, the robot boots with no network.

<Accordion title="Fix an error">
  The error names the file, then the line and the column where the typo sits. These three are the likely ones.

  ```
  /etc/netplan/01-netcfg.yaml:1:55: Error in network definition: address '192.168.10.42' is missing /prefixlength
  ```

  The mask is missing after the address. Add `/24`, or the short form from the table.

  ```
  /etc/netplan/01-netcfg.yaml:2:1: Invalid YAML: did not find expected ',' or '}':
  ```

  A brace is missing. The line has to end with `]}}}}` before the closing quote.

  ```
  /etc/netplan/01-netcfg.yaml:1:100: Error in network definition: unknown key 'via:192.168.10.1'
  ```

  A space is missing after a colon. Every `:` and every `,` in the line is followed by a space. On Ubuntu 18.04, this error reads `Invalid YAML: found unexpected ':'` instead.

  To fix the line, press the up arrow twice to bring back the `echo` command. Correct it, press Enter to rewrite the file, then run `sudo netplan generate` again.
</Accordion>

Once the check comes back clean, reboot the robot.

```bash
sudo reboot
```

The platform needs about three minutes to notice the robot is back. Then it reads **Online** in [your list of robots](/equipment/agents). Still **Offline**? Work through [checking the robot's network connection](/hardware/check-robot-network).

## Go back to the old address

Delete the new configuration, put the old one back, then reboot:

```bash
sudo rm /etc/netplan/01-netcfg.yaml
sudo mv /etc/netplan-backup/*.yaml /etc/netplan/
sudo reboot
```
