Afficher l'identité avec laquelle le CLI s'authentifie (clé API ou token OAuth stocké)

## Utilisation

```bash
ktm whoami [flags]
```

## Exemples

```bash
# Afficher l'identité derrière les identifiants effectifs
ktm whoami

# Enveloppe lisible par machine pour les scripts
ktm whoami -o json
```

## Flags

| Flag | Type | Défaut | Description |
| --- | --- | --- | --- |
| `--creds-file` | string |  | Chemin vers le fichier d'identifiants de secours |
| `--no-keychain` | boolean |  | Opère sur le fichier de secours plutôt que sur le trousseau de clés OS |

## Détails

Affiche l'identité derrière les identifiants effectifs du CLI, en suivant le même
ordre de résolution que toutes les autres commandes :

  1. Clé API (--api-key-file, puis KAPPTIVATE_API_KEY) : échangée auprès de la
     plateforme contre un JWT ; les claims d'identité sont décodés depuis celui-ci (un appel réseau).
  2. Token OAuth stocké par 'ktm login' : lecture locale uniquement, aucun appel réseau.

Le code de sortie 0 signifie que le CLI dispose d'identifiants fonctionnels ; 2 signifie
que ce n'est pas le cas (aucun identifiant, token expiré ou clé API rejetée). Les claims
sont affichés comme valeurs décodées du payload JWT, sans vérification.

<Note>
  Les flags globaux (`--output`, `--debug`, `--host`, ...) s'appliquent à toutes les commandes. Consultez la [vue d'ensemble de la référence des commandes](/fr/cli/commands/overview).
</Note>
