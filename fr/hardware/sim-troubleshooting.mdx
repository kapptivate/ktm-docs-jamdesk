Changer la carte ne règle le problème que si c'est la carte qui est en cause. Quand une SIM n'exécute plus de tests, le problème peut aussi venir du slot qui la porte, ou du réseau de l'opérateur. Cette page vous aide à trancher entre les trois, à partir de ce qu'affiche la plateforme.

Elle concerne les SIM des robots cellulaires.

## Avant de vous déplacer

Ouvrez la SIM dans le [**Devices lab**](/fr/equipment/devices-lab) et relevez le robot et le slot qui l'hébergent, son numéro, son **Status** et sa valeur **Network**.

Regardez ensuite les autres SIM du même robot et du même site. Si le problème ne concerne qu'une seule SIM, l'investigation porte sur la carte et sur son slot. Si toutes les SIM d'un même opérateur tombent à la même minute, sur plusieurs robots, l'investigation porte sur le réseau de cet opérateur, et la carte n'est pas en cause.

## Ce qu'il vous faut sur place

- Un téléphone désimlocké, pour tester la carte hors du robot.
- Une SIM qui fonctionne sur le même robot, pour permuter les slots.
- Pour un robot 4G, l'outil d'éjection des tiroirs SIM.

## Par où commencer

Dans tous les cas, commencez par redémarrer le slot, avec le bouton **Reboot slot** en haut de la page de la SIM ou dans le menu de sa ligne.

| Ce que vous constatez | Ce qu'il faut vérifier | Où aller |
|---|---|---|
| **Network** reste sur **Denied** ou **Not registered (denied)** | l'abonnement associé à la carte | [La carte est lue, le réseau la refuse](#la-carte-est-lue-le-réseau-la-refuse) |
| Le slot affiche **No SIM inserted** alors qu'une carte est insérée | la carte et le contact du slot | [La carte n'est plus détectée](#la-carte-nest-plus-détectée) |
| **Network** affiche **Searching** ou **Not registered** depuis plus de dix minutes | l'activation, la radio, la technologie d'accès | [Une SIM bloquée sur Searching](#une-sim-bloquée-sur-searching) |
| La SIM affiche **Unnamed**, au statut **Configuration** | son numéro dans la plateforme | [Remplacer une SIM](/fr/hardware/swap-sim) |
| La SIM semble saine, mais un test échoue avec un message | le message lui-même | [Les messages d'erreur des tests](#les-messages-derreur-des-tests) |

## La carte est lue, le réseau la refuse

Le robot lit la carte et le signal est bon, mais le réseau refuse de l'enregistrer. Dans ce cas, la carte n'a rien. Une carte neuve semble régler le problème uniquement parce qu'elle porte un nouvel IMSI, donc un nouvel abonnement.

La cause la plus probable est un blocage de l'IMSI pour usage anormal, par une règle antifraude ou un plafond d'usage, car les monitors sollicitent les SIM d'un robot en continu. Demandez à votre équipe HLR de vérifier le statut de l'IMSI avant de remplacer quoi que ce soit.

## La carte n'est plus détectée

Le slot affiche **No SIM inserted** alors que la carte est bien insérée. Un redémarrage seul ne la fait pas réapparaître : soit la carte est en fin de vie, soit le contact du slot est usé.

Retirez la carte, réinsérez-la, puis redémarrez le slot. Si elle n'apparaît toujours pas, [distinguez la carte du slot](#distinguer-la-carte-du-slot).

## Une SIM bloquée sur Searching

Une SIM qui reste sur **Searching** au bout de dix minutes ne se débloque pas toute seule. Vérifiez trois points, dans cet ordre.

- **La ligne est active.** Une carte neuve qui n'a pas été activée dans le HLR reste sur **Searching**, tout comme une ligne suspendue.
- **La radio atteint le robot.** Si la SIM échoue dans tous les slots, comparez le signal avec celui d'un robot du même modèle installé sur un autre site. Si le signal est nettement plus faible ici, vérifiez que les antennes sont bien vissées, puis déplacez le robot.
- **Le test n'impose pas une technologie absente.** Un test qui force la 3G ou la 2G sur une cellule qui ne la diffuse plus laisse la SIM en recherche. Réglez **Access technology** sur **Default**, sauf si le test vérifie volontairement la 3G ou la 2G.

## Distinguer la carte du slot

**Permutez les slots.** Insérez la carte en défaut dans le slot d'une SIM qui fonctionne sur le même robot, et cette SIM dans le slot en défaut. Redémarrez les deux slots. Si le défaut suit la carte, c'est la carte ou son abonnement qui est en cause. Si le défaut reste sur le slot, c'est le slot qui est en cause.

**Testez la carte dans un téléphone.** Si la carte ne s'enregistre pas non plus dans un téléphone, ne reçoit pas de SMS ou si le code USSD n'aboutit pas, le robot n'est pas en cause.

Quand le défaut reste sur le slot, vérifiez une dernière piste : un IMEI banni par l'opérateur empêche toute carte de s'enregistrer dans ce slot. Demandez l'IMEI du slot à support@kapptivate.com, puis faites-le vérifier dans l'EIR par votre équipe cœur de réseau.

## Remplacer la carte ou faire réparer le robot

- **Le défaut suit la carte, et le HLR ne signale rien** : remplacez la carte en suivant [Remplacer une SIM](/fr/hardware/swap-sim).
- **Le défaut reste sur le slot, et l'IMEI n'est pas banni** : le slot est défaillant.
- **Un slot a déjà usé deux cartes** : n'en insérez pas une troisième, le slot est défaillant.

Pour un slot défaillant, écrivez à support@kapptivate.com en indiquant le nom du robot tel qu'il apparaît sur la plateforme, et le numéro du slot.

## Les messages d'erreur des tests

Les messages ci-dessous sont ceux qu'émet le robot, cités mot pour mot. Tout autre texte est la réponse du réseau lui-même : un menu, un solde, ou une erreur de passerelle comme `USSDC: ESME fault.` ou `Service not available`. Dans ce cas, la SIM fonctionne et le réseau a répondu. Transmettez le texte à l'équipe qui gère le service appelé par ce code.

### USSD

| Message | Ce qu'il faut faire |
|---|---|
| `Connection problem or invalid MMI code (+CME ERROR: 100)` | Le réseau a rejeté la requête. Si plusieurs SIM échouent à partir de la même minute, la plateforme USSD est en cause : pour le confirmer, rejouez le code sur une autre SIM du site en [live session](/fr/tests/live-session). Si une seule SIM est touchée, redémarrez son slot, puis testez la carte dans un téléphone. |
| `Connection problem or invalid MMI code (+CME ERROR: 258)` | La SIM refuse les requêtes USSD. Redémarrez le slot, puis faites vérifier le profil de la ligne par votre équipe réseau. |
| `No network service (+CME ERROR: 30)` | Regardez la colonne **Network**. Si la SIM est enregistrée, la cause est côté réseau. |
| `Call barred (+CME ERROR: 257)` | Levez l'interdiction d'USSD sur la ligne. |
| `Network Timeout (+CUSD 5)`, `no ussd response received from network` ou `Ussd session closed by operator (+CUSD:2)` | Le réseau n'a pas répondu, ou a fermé la session avant la fin : mauvaise couverture, licence USSD expirée ou serveur USSD surchargé. Transmettez à l'équipe qui gère votre plateforme USSD le code, l'heure et le numéro de la SIM. |
| `Wrong USSD code format` | Corrigez le champ **Command** du test. |

### SMS

| Message | Ce qu'il faut faire |
|---|---|
| `SMS not received.` | Testez la carte dans un téléphone. Si elle ne reçoit rien non plus, vérifiez la ligne et le SMSC. Si tous les tests SMS d'un robot échouent en même temps, écrivez à support@kapptivate.com : une horloge décalée de plus de 30 secondes fait échouer tous les tests SMS du robot. Le reste de ses tests fonctionne tant que le décalage reste sous deux minutes. |
| `Received SMS was not the expected one.` | Comparez le SMS au champ **Expected Message** du test. Le service a peut-être changé son message, ou répondu par une erreur, un solde vide par exemple. |
| `failed to send sms` | Vérifiez le crédit de la ligne, puis son SMSC. |

### Appels

| Message | Ce qu'il faut faire |
|---|---|
| `cannot place call to <NUMBER>` | Vérifiez que la SIM appelante est enregistrée et qu'elle a du crédit. |
| `call was correctly emitted but was suddenly stopped` | Soit la SIM n'a plus de crédit, soit elle n'est pas autorisée à appeler ce numéro (numéros courts, ou itinérance). |
| `timeout call not pick up` | Vérifiez que la SIM appelée est enregistrée. |
| `timeout no call received` | Lisez le résultat du côté appelant, et vérifiez le numéro qu'il compose. |

### Data

| Message | Ce qu'il faut faire |
|---|---|
| `No internet after PDP activation` | Le forfait data est épuisé ou a expiré : rechargez la ligne. |
| `Failed to activate PDP context (timeout while waiting cellular network attachment)` | La SIM n'est pas attachée au réseau. Reprenez [par où commencer](#par-où-commencer). |
| `Failed to activate PDP context (no 'APN' specified)` | Dans le test, réactivez **Use default APN credentials**, ou renseignez **APN Name**. |
| `Failed to activate PDP context (Unspecified reason)` | Vérifiez l'APN et l'abonnement data de la ligne. |

### Technologie réseau

Le robot change de technologie avant d'exécuter l'action. Ces messages apparaissent donc en premier.

| Message | Ce qu'il faut faire |
|---|---|
| `failed to change network technology: sim not registered` ou `failed to change network technology: timeout while waiting network registration` | La SIM n'est pas enregistrée sur la technologie demandée. Réglez **Access technology** sur **Default**, sauf si le test vérifie volontairement une technologie. Si l'erreur persiste avec **Default**, reprenez [par où commencer](#par-où-commencer). |
| `failed to change network technology: ERROR` | Redémarrez le slot. Si l'erreur persiste, écrivez à support@kapptivate.com. |

### Robot et test

| Message | Ce qu'il faut faire |
|---|---|
| `Robot unreachable` | Le robot est **Offline** : suivez [Dépanner un robot Offline](/fr/hardware/network-troubleshooting). |
| `SIM timeout` | Le slot n'a pas répondu dans le délai, de quatre minutes par défaut. Redémarrez le slot. Si l'erreur revient, écrivez à support@kapptivate.com. |
| `Owner <NUMBER> not recognized` | Aucune SIM de votre espace de travail ne porte ce numéro en ce moment. Modifiez le test ou le monitor pour sélectionner une SIM disponible. Après un remplacement, vous pouvez aussi attribuer ce numéro à la nouvelle SIM, en suivant [Remplacer une SIM](/fr/hardware/swap-sim). |

## Qui contacter

Quand le défaut suit la carte ou vient du réseau, ce sont vos propres équipes qui prennent la main : le HLR pour un IMSI refusé ou une ligne inactive, le cœur de réseau pour un IMEI banni, la plateforme USSD pour une requête restée sans réponse. Pour tout le reste, écrivez à support@kapptivate.com en indiquant le nom du robot tel qu'il apparaît sur la plateforme, le numéro du slot, le message exact et l'heure de l'échec.
