---
title: Vérifier la connexion réseau d'un robot
description: Depuis un terminal sur le robot, vérifier son adresse IP locale, sa passerelle et les flux que votre service informatique doit ouvrir, puis demander le déploiement d'un nouveau robot.
---

Deux situations mènent à cette page. Vous venez de configurer le réseau d'un nouveau robot, et vous voulez vérifier qu'il atteint Kapptivate avant de demander son déploiement.

Ou bien un robot en service est passé **Offline**, et il le reste après deux redémarrages physiques alors que son alimentation et ses câbles sont en ordre.

Dans les deux cas, les vérifications se font dans un terminal sur le robot. Elles indiquent si le blocage vient du robot ou de votre réseau.

Si le robot est **Offline** et que vous ne l'avez pas encore redémarré, commencez par [dépanner un robot Offline](/fr/hardware/network-troubleshooting).

## Ce qu'il vous faut sur place

- Un écran, un clavier, une souris et un câble vidéo, HDMI ou VGA selon le modèle de robot, branchés à l'arrière du robot.
- Les identifiants du robot. Demandez-les à support@kapptivate.com si vous ne les avez pas.
- Sur un réseau d'entreprise filtré, le document des exigences IP, qui liste les flux nécessaires au fonctionnement du robot. Demandez-le à support@kapptivate.com.
- Sur un réseau d'entreprise filtré toujours, l'adresse IP locale, sur votre LAN, pour laquelle ces flux ont été ouverts. C'est votre service informatique qui la détient.

## Vérifier l'adresse IP locale du robot

Connectez-vous avec les identifiants du robot, puis ouvrez un terminal depuis le bureau Linux. Sur un ancien robot, sans bureau, tapez les commandes directement sur sa console. Une seule commande donne l'adresse IP locale et la passerelle.

```bash
ip route get 1.1.1.1
```

```
1.1.1.1 via 192.168.10.1 dev eno1 src 192.168.10.42 uid 1000
    cache
```

`src` donne l'adresse IP locale du robot, ici `192.168.10.42`, et `via` donne la passerelle de son réseau, ici `192.168.10.1`. Sur un réseau filtré, comparez l'adresse `src` à celle que votre service informatique a déclarée dans ses règles de pare-feu : les deux doivent coïncider. Si elles sont différentes, vous pouvez reconfigurer l'IP statique du robot pour qu'elle corresponde à ce qui est configuré sur votre réseau : voir [définir une IP statique](/fr/hardware/configure-network#trouver-le-port-ethernet).

L'autre réponse possible est celle-ci.

```
RTNETLINK answers: Network is unreachable
```

Le robot n'a aucune route, donc aucun lien. Vérifiez le câble RJ45 et le port du switch.

Joignez ensuite la passerelle, en reprenant l'adresse affichée après `via`.

```bash
ping -c 4 192.168.10.1
```

```
PING 192.168.10.1 (192.168.10.1) 56(84) bytes of data.
64 bytes from 192.168.10.1: icmp_seq=1 ttl=254 time=1.12 ms
64 bytes from 192.168.10.1: icmp_seq=2 ttl=254 time=1.18 ms
64 bytes from 192.168.10.1: icmp_seq=3 ttl=254 time=1.09 ms
64 bytes from 192.168.10.1: icmp_seq=4 ttl=254 time=1.15 ms

--- 192.168.10.1 ping statistics ---
4 packets transmitted, 4 received, 0% packet loss, time 3004ms
rtt min/avg/max/mdev = 1.090/1.135/1.180/0.034 ms
```

La passerelle répond : le robot est bien sur son réseau, [passez aux flux](#vérifier-les-flux). L'autre réponse est celle-ci.

```
PING 192.168.10.1 (192.168.10.1) 56(84) bytes of data.

--- 192.168.10.1 ping statistics ---
4 packets transmitted, 0 received, 100% packet loss, time 3007ms
```

Vérifiez alors le câble RJ45 : il est peut-être défaillant, ou branché au mauvais endroit. Faites ensuite vérifier par votre service informatique qu'il aboutit sur un port de switch actif.

## Vérifier les flux

Si votre robot sort directement sur internet, vous n'avez aucun flux à ouvrir : la page s'arrête pour vous à la passerelle. Ce qui suit ne vaut que sur un réseau d'entreprise filtré.

Le document des exigences IP liste les flux à ouvrir, et la commande qui teste chacun. Lancez ces tests depuis le robot, pas depuis votre ordinateur.

Notez pour votre service informatique chaque ligne qui ne répond pas `succeeded!`.

### Rejouer le test par le nom de domaine

Vérifiez ensuite les flux du document qui ont un nom de domaine, avec ce nom à la place de l'adresse IP.

```bash
nc -zv -w 5 robots.example.com 443
```

Le nom se résout et le flux passe :

```
Connection to robots.example.com (203.0.113.10) 443 port [tcp/https] succeeded!
```

L'autre réponse est celle-ci :

```
nc: getaddrinfo for host "robots.example.com" port 443: Name or service not known
```

L'adresse IP passe mais son nom échoue. Le robot n'a certainement pas de serveur DNS configuré, ce qui l'empêche de résoudre le nom de domaine. Remontez l'information à votre service informatique. Vous pouvez configurer un ou plusieurs serveurs DNS sur le robot en suivant l'étape [saisir les adresses](/fr/hardware/configure-network#saisir-les-adresses) de la configuration réseau.

### Vérifier le certificat

Dernière vérification : le code de retour de votre plateforme Kapptivate, à l'adresse que vous ouvrez dans votre navigateur.

```bash
curl -sS -o /dev/null -w '%{http_code}\n' https://exemple.kapptivate.com
```

La commande affiche un code à trois chiffres, par exemple `200` ou `404` :

```
200
```

Quel que soit ce code, la connexion chiffrée a abouti et le certificat est reconnu. L'autre réponse est une erreur `curl: (60)`, suivie de `000` :

```
curl: (60) SSL certificate problem: unable to get local issuer certificate
More details here: https://curl.se/docs/sslcerts.html

curl failed to verify the legitimacy of the server and therefore could not
establish a secure connection to it. To learn more about this situation and
how to fix it, please visit the web page mentioned above.
000
```

Un équipement de votre réseau s'intercale entre le robot et Kapptivate, et présente son propre certificat. Remontez à votre service informatique que le trafic HTTPS vers Kapptivate est intercepté.

## Demander le déploiement d'un nouveau robot

Toutes les étapes de vérification ont fonctionné sur un nouveau robot ? Il ne reste qu'à demander son déploiement au support, qui le rend opérationnel sur Kapptivate. Relevez le numéro de série du robot dans un terminal :

```bash
sudo krobot serial
```

Envoyez la sortie de cette commande à support@kapptivate.com. Joignez-y l'IP statique si vous en avez défini une. Le support déploie ensuite le robot, et il passe **Online** dans [la liste de vos robots](/fr/equipment/agents), sans autre action de votre part. C'est le feu vert pour le [visser en baie](/fr/hardware/install-robot#monter-le-robot-en-baie).

## Qui contacter

Une des étapes de vérification de cette procédure a échoué : le blocage est sur votre réseau. Transmettez la sortie complète des commandes concernées à votre service informatique, avec l'adresse IP locale du robot et l'heure du test.

Toutes les étapes de vérification ont fonctionné, et un robot en service reste **Offline** ? Écrivez à support@kapptivate.com. Donnez le nom du robot tel qu'il apparaît sur la plateforme, et son adresse IP locale si vous l'avez relevée : cela facilitera les investigations.
