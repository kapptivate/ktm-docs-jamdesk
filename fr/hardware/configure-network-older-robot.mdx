---
title: Changer l'IP d'un ancien robot
description: Donner une nouvelle adresse IP, une passerelle et un serveur DNS à un robot sans bureau, en quelques commandes tapées sur sa console.
---

Un ancien robot n'a pas d'interface graphique : son adresse IP se change en ligne de commande, directement sur sa console. Entre le moment où vous changez l'adresse et celui où le robot repasse **Online**, il n'exécute aucun test.

Cette page concerne les robots qui affichent une ligne de commande dès la connexion. Si vous voyez un bureau Linux, suivez plutôt [configurer le réseau du robot](/fr/hardware/configure-network).

## Avant de commencer

- Un écran et un clavier. Selon le modèle, l'écran se branche en HDMI ou en VGA.
- Les identifiants du robot. Demandez-les à support@kapptivate.com si vous ne les avez pas.
- La nouvelle adresse IP, son masque, la passerelle et le serveur DNS, fournis par votre service informatique.
- Sur un réseau d'entreprise filtré, les flux ouverts pour la nouvelle adresse. Ils sont listés dans le document des exigences IP : demandez-le à support@kapptivate.com. Sans ces flux, le robot reste **Offline** sur sa nouvelle adresse.

## Se connecter

Branchez l'écran et le clavier à l'arrière du robot, puis saisissez le nom d'utilisateur et le mot de passe. Le mot de passe ne s'affiche pas pendant la saisie, c'est normal.

<Note>
  Le robot attend un clavier AZERTY, ou QWERTY sur certains robots. Tapez `a` à l'invite de connexion : si un `q` s'affiche, branchez un clavier de l'autre disposition.
</Note>

Si `sudo` demande un mot de passe dans la suite de la page, saisissez celui de votre connexion.

## Repérer le port

```bash
ip -br link | grep ^en
```

```
enp1s0           DOWN           00:00:5e:00:53:01 <BROADCAST,MULTICAST>
enp2s0           UP             00:00:5e:00:53:02 <BROADCAST,MULTICAST,UP,LOWER_UP>
```

Le câble est branché sur le port qui affiche `UP` dans la deuxième colonne, ici `enp2s0`. Notez ce nom.

Si aucun port n'affiche `UP`, branchez le câble sur un autre port et relancez la commande. Si plusieurs ports affichent `UP`, le robot est relié à plusieurs réseaux : arrêtez-vous et écrivez à support@kapptivate.com.

## Écrire la nouvelle adresse

Affichez d'abord les fichiers réseau du robot :

```bash
ls /etc/netplan
```

Si la liste contient `50-cloud-init.yaml`, lancez cette commande. Sans elle, le robot remet son ancienne configuration à chaque démarrage.

```bash
echo "network: {config: disabled}" | sudo tee /etc/cloud/cloud.cfg.d/99-disable-network-config.cfg
```

Mettez ensuite l'ancienne configuration de côté. Le dossier `/etc/netplan-backup` la garde, pour [revenir à la configuration précédente](#revenir-à-la-configuration-précédente) si besoin.

```bash
sudo mkdir -p /etc/netplan-backup
sudo mv /etc/netplan/*.yaml /etc/netplan-backup/
```

Écrivez enfin la nouvelle configuration, en remplaçant les valeurs en capitales :

```bash
echo "network: {version: 2, ethernets: {PORT: {addresses: [ADDRESS/PREFIX], routes: [{to: 0.0.0.0/0, via: GATEWAY}], nameservers: {addresses: [DNS]}}}}" | sudo tee /etc/netplan/01-netcfg.yaml
```

- `PORT` : le port qui affichait `UP`, par exemple `enp2s0`.
- `ADDRESS/PREFIX` : la nouvelle adresse IP, une barre oblique, puis le masque sous sa forme courte, donnée par le tableau ci-dessous. Par exemple `192.168.10.42/24`.
- `GATEWAY` : l'adresse de la passerelle.
- `DNS` : l'adresse du serveur DNS. S'il y en a deux, séparez-les par une virgule et une espace.

| Masque | Forme courte |
|---|---|
| 255.255.0.0 | /16 |
| 255.255.240.0 | /20 |
| 255.255.252.0 | /22 |
| 255.255.254.0 | /23 |
| 255.255.255.0 | /24 |
| 255.255.255.128 | /25 |
| 255.255.255.192 | /26 |
| 255.255.255.224 | /27 |

Si votre masque n'est pas dans le tableau, demandez sa forme courte à votre service informatique.

Par exemple, pour un robot en `192.168.10.42` sur un réseau `255.255.255.0` :

```bash
echo "network: {version: 2, ethernets: {enp2s0: {addresses: [192.168.10.42/24], routes: [{to: 0.0.0.0/0, via: 192.168.10.1}], nameservers: {addresses: [192.168.10.53]}}}}" | sudo tee /etc/netplan/01-netcfg.yaml
```

La commande réaffiche la ligne, qui est désormais le contenu du fichier.

## Vérifier et redémarrer

Vérifiez le fichier :

```bash
sudo netplan generate
```

Si le fichier est valide, la commande n'affiche rien, ou cet avertissement, qui ne bloque rien :

```
** (generate:1225): WARNING **: 15:24:04.849: Permissions for /etc/netplan/01-netcfg.yaml are too open. Netplan configuration should NOT be accessible by others.
```

Si elle affiche une erreur, corrigez la ligne avant de redémarrer : avec un fichier invalide, le robot démarre sans réseau.

<Accordion title="Corriger une erreur">
  L'erreur commence par le nom du fichier, suivi du numéro de ligne et du numéro de colonne où se trouve la faute. Voici les trois erreurs les plus probables.

  ```
  /etc/netplan/01-netcfg.yaml:1:55: Error in network definition: address '192.168.10.42' is missing /prefixlength
  ```

  Le masque manque après l'adresse. Ajoutez `/24`, ou la forme courte donnée par le tableau.

  ```
  /etc/netplan/01-netcfg.yaml:2:1: Invalid YAML: did not find expected ',' or '}':
  ```

  Une accolade manque. La ligne doit se terminer par `]}}}}` avant le guillemet final.

  ```
  /etc/netplan/01-netcfg.yaml:1:100: Error in network definition: unknown key 'via:192.168.10.1'
  ```

  Une espace manque après un deux-points. Dans la ligne, chaque `:` et chaque `,` est suivi d'une espace. Sous Ubuntu 18.04, cette erreur s'affiche sous la forme `Invalid YAML: found unexpected ':'`.

  Pour corriger, appuyez deux fois sur la flèche du haut : la commande `echo` réapparaît. Corrigez-la, appuyez sur Entrée pour réécrire le fichier, puis relancez `sudo netplan generate`.
</Accordion>

Quand la vérification ne signale plus d'erreur, redémarrez le robot :

```bash
sudo reboot
```

Laissez à la plateforme environ trois minutes, puis relisez le statut du robot dans [la liste de vos robots](/fr/equipment/agents). Il doit repasser **Online**. S'il reste **Offline**, suivez [vérifier la connexion réseau du robot](/fr/hardware/check-robot-network).

## Revenir à la configuration précédente

Supprimez la nouvelle configuration, remettez l'ancienne en place, puis redémarrez :

```bash
sudo rm /etc/netplan/01-netcfg.yaml
sudo mv /etc/netplan-backup/*.yaml /etc/netplan/
sudo reboot
```
