Configurez n'importe quel client compatible MCP sur votre endpoint, et authentifiez-vous soit via une connexion navigateur (OAuth), soit avec l'en-tête `X-Kapptivate-API-Key`. Cette page couvre les clients développeur courants (Claude Code, Cursor, Claude Desktop et GitHub Copilot). Pour Microsoft 365 Copilot Studio et Google Gemini, consultez leurs pages dédiées dans cette section.

## Votre endpoint

Vous ouvrez votre session Kapptivate sur app.kapptivate.com ? Voici votre endpoint :

```
https://mcp.kapptivate.com/mcp
```

Si vous ouvrez votre session Kapptivate sur une autre adresse, votre endpoint porte le nom de votre environnement. Reprenez la première partie de l'adresse de connexion et placez-la après `/t/` :

```
https://mcp.kapptivate.com/t/<environment>/mcp
```

Un compte sur `acme.kapptivate.com` se connecte donc à `https://mcp.kapptivate.com/t/acme/mcp`. Tous les exemples de cette page portent l'adresse app.kapptivate.com : remplacez-la par la vôtre avant d'en copier un.

## Obtenir votre clé API

<Steps>
  <Step title="Ouvrir votre profil">
    Ouvrez votre session Kapptivate à l'adresse qui est la vôtre, celle qui vient de vous donner votre endpoint, puis ouvrez votre profil.
  </Step>
  <Step title="Copier votre clé API">
    Copiez votre clé API personnelle. Elle porte le même accès que votre compte. Les clés au niveau workspace, scopées par équipe, se gèrent dans [Administration > Clés API](/fr/administration/api-keys).
  </Step>
</Steps>

<Warning>
  Traitez la clé comme un mot de passe. Préférez une variable d'environnement plutôt que de la coller dans un fichier de configuration que vous pourriez commiter.
</Warning>

<Note>
  Vous préférez une connexion via le navigateur ? Les clients qui implémentent l'autorisation MCP (les connecteurs personnalisés Claude, par exemple) peuvent se passer complètement de clé API : ajoutez l'URL du serveur sans aucun en-tête et le client vous guide dans une connexion navigateur (OAuth). Cela vaut pour les clients qui portent nativement l'autorisation MCP, comme les connecteurs personnalisés Claude. En revanche `mcp-remote` n'y arrive pas : ce relais réclame l'enregistrement dynamique de client, que le serveur d'autorisation ne propose pas, et il s'arrête au démarrage sur `Incompatible auth server`. Gardez donc la clé API pour la configuration Claude Desktop ci-dessous.
</Note>

## Portée des accès

Une connexion navigateur accorde trois scopes. Une clé API, elle, porte tous les droits de votre compte.

| Scope | Ce qu'il autorise |
| --- | --- |
| `read` | Consulter toutes les ressources Kapptivate : tests, monitors, dashboards, métriques, robots |
| `write` | Créer, modifier et exécuter ces ressources |
| `admin` | Actions privilégiées : commandes shell sur les robots, redémarrage et maintenance, clôture d'incidents |

Le scope `admin` autorise un assistant à redémarrer vos robots. Lisez l'écran de consentement avant de valider. Pour savoir ce qu'un client détient aujourd'hui, ou pour le lui retirer, ouvrez `https://<votre-environnement>/o/authorized_tokens/`. La révocation coupe cet accès immédiatement et ne change rien d'autre.

## Configurer votre client

<Tabs>
<Tab title="Claude Code">

Enregistrez le serveur avec une seule commande, puis vérifiez la connexion :

```bash
claude mcp add --transport http kapptivate https://mcp.kapptivate.com/mcp \
  --header "X-Kapptivate-API-Key: $KAPPTIVATE_API_KEY"

claude mcp list
```

</Tab>
<Tab title="Cursor">

Ajoutez Kapptivate à votre configuration MCP (Settings, puis MCP) :

```json
{
  "mcpServers": {
    "kapptivate": {
      "url": "https://mcp.kapptivate.com/mcp",
      "headers": {
        "X-Kapptivate-API-Key": "YOUR_KEY"
      }
    }
  }
}
```

</Tab>
<Tab title="Claude Desktop">

Claude Desktop accède aux serveurs distants via `mcp-remote`. Modifiez `claude_desktop_config.json`, puis redémarrez Claude Desktop :

```json
{
  "mcpServers": {
    "kapptivate": {
      "command": "npx",
      "args": [
        "-y", "mcp-remote",
        "https://mcp.kapptivate.com/mcp",
        "--header", "X-Kapptivate-API-Key:YOUR_KEY"
      ]
    }
  }
}
```

</Tab>
<Tab title="GitHub Copilot">

Dans VS Code, ajoutez un fichier `.vscode/mcp.json` à votre workspace (ou lancez **MCP: Open User Configuration** pour l'appliquer partout) :

```json
{
  "inputs": [
    {
      "type": "promptString",
      "id": "kapptivate-key",
      "description": "Kapptivate API key",
      "password": true
    }
  ],
  "servers": {
    "kapptivate": {
      "type": "http",
      "url": "https://mcp.kapptivate.com/mcp",
      "headers": {
        "X-Kapptivate-API-Key": "${input:kapptivate-key}"
      }
    }
  }
}
```

Ouvrez Copilot Chat en mode agent, puis démarrez le serveur depuis **MCP: List Servers** dans la Palette de commandes. VS Code demande la clé à la première utilisation et la stocke de façon sécurisée.

<Note>
  Il s'agit de GitHub Copilot dans votre éditeur. C'est un produit différent de [Microsoft Copilot Studio](/fr/mcp/integrations/copilot-studio) (le constructeur d'agents Microsoft 365).
</Note>

</Tab>
</Tabs>

## Vérifier la connexion

Demandez à votre assistant quelque chose en lecture seule, par exemple : "Liste les operators auxquels j'ai accès." Si des résultats apparaissent, vous êtes connecté.

## Erreurs courantes

L'établissement de la connexion prouve seulement que l'adresse existe. Votre environnement, lui, se résout plus tard, au moment où un outil s'exécute : un client peut donc afficher la connexion comme établie et échouer dès son premier appel. Dans ses messages d'erreur, le serveur appelle un environnement un tenant.

<Warning>
  Un statut de connexion au vert ne valide pas votre endpoint. Lancez [la vérification en lecture seule ci-dessus](#vérifier-la-connexion).
</Warning>

| Ce que vous voyez | Ce que cela signifie | Ce qu'il faut faire |
| --- | --- | --- |
| 401 | Aucune authentification, ou une authentification émise pour un autre environnement | Envoyez votre clé API dans l'en-tête `X-Kapptivate-API-Key`, ou connectez-vous par le navigateur, qui transporte à la place une session `Authorization: Bearer`. La clé doit appartenir à l'environnement présent dans l'URL. |
| 404 | Le segment `/t/` manque au chemin | Écrivez `https://mcp.kapptivate.com/t/<environment>/mcp`, jamais `https://mcp.kapptivate.com/<environment>/mcp`. |
| 400, `invalid tenant path` | Le chemin porte une adresse complète | Ne gardez que la première partie de votre adresse de connexion, sans `.kapptivate.com`. |
| La connexion s'établit, puis tous les appels d'outil échouent | La clé et le chemin désignent deux environnements différents | Alignez-les, puis reconnectez le client. |

Rien n'y fait ? Écrivez à support@kapptivate.com en indiquant l'endpoint utilisé et le code obtenu.
