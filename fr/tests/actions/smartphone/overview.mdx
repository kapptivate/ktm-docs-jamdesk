Les tests smartphone exécutent votre application native sur de vrais devices Android et iOS. Ils sont construits à partir des étapes ci-dessous ; les groupes correspondent aux catégories de la palette **Ajouter une étape** dans le [test builder](/fr/tests/builder), ce que vous voyez ici est ce que vous voyez dans le produit.

Chaque test smartphone commence par une étape verrouillée **Ouvrir l'application** qui ouvre l'application sélectionnée lors de la création du test.

## Interactions

| Étape | Description |
|------|-------------|
| [Toucher](/fr/tests/actions/smartphone/tap) | Appuyer sur un élément, ou sur une position X/Y exacte en mode Coordonnées |
| [Appui long](/fr/tests/actions/smartphone/longpress) | Appui long pour ouvrir les actions contextuelles |
| [Masquer le clavier](/fr/tests/actions/smartphone/hidekeyboard) | Masquer le clavier virtuel |
| [Remplir le champ](/fr/tests/actions/smartphone/input) | Saisir du texte, des variables ou des données générées dans un champ |

## Paramètres communs des étapes

Chaque étape partage quelques paramètres, visibles dans le panneau latéral de l'étape dans le builder :

- **Ignorer les erreurs sur cette étape** (`ignore_errors`) : l'exécution continue avec l'étape suivante même si celle-ci échoue.
- **Désactiver pendant l'exécution** (`disabled`) : l'étape reste dans le scénario mais n'est pas exécutée.
- **Capacités personnalisées** (`use_capabilities`, `capabilities`) : ajuster ou remplacer le comportement d'exécution pour cette étape uniquement.

Les étapes qui ciblent un élément partagent aussi les paramètres IA : une **description** en langage naturel, un **sélecteur manuel** optionnel (XPath ou CSS), et une **stratégie IA** qui détermine quand l'IA localise l'élément par rapport au sélecteur enregistré. Sur les étapes d'interaction smartphone, l'IA est désactivée par défaut ; activez-la par étape ou via la stratégie du test. Voir [Sélecteurs IA](/fr/ai/selectors).

## Des résultats aux analytiques

Chaque étape enregistre son timing, son statut et ses captures d'écran, ainsi que les variables créées. Au niveau du test, chaque exécution alimente la mesure `test` utilisée par les [Analytiques](/fr/analytics/dashboards) : durée, compteurs de succès/avertissement/échec, et en cas d'échec, quel type d'étape a provoqué l'erreur. Les métriques personnalisées créées dans les étapes remontent au même endroit.
