---
title: "Vérifier un élément dans un test smartphone"
sidebarTitle: "Vérifier l'élément"
description: Vérifier qu'un élément est (ou n'est pas) affiché, cliquable, activé ou présent.
---

Utilisez-la pour confirmer ce que l'utilisateur doit voir : l'écran de confirmation est affiché, le bouton Continuer est activé, le spinner de chargement a disparu. L'étape attend que la condition soit remplie et échoue si elle ne l'est jamais dans le temps imparti. C'est l'étape de vérification principale pour les tests smartphone, et une alternative robuste aux délais fixes.

## Paramètres

| Paramètre | Requis | Description |
| ----------- | -------- | ------------- |
| Élément ciblé | Oui, sauf si un sélecteur manuel est défini | Description en langage naturel de l'élément à vérifier. |
| Sélecteur manuel | Non | Sélecteur XPath ou CSS, utilisé lorsque l'IA est désactivée ou comme sélecteur enregistré. |
| Condition | Oui | `is` ou `is not`. `is not` vérifie le contraire de l'état choisi. |
| État | Oui | L'état à vérifier. Par défaut : `displayed` (libellé "affiché" dans le builder). `exist` est libellé "présent" dans le builder : l'élément est dans l'arbre UI, visible ou non. |
| Temps d'attente max. | Non | Combien de temps attendre la condition avant l'échec, en secondes. |
| Ignorer les erreurs sur cette étape | Non | L'exécution continue avec l'étape suivante si celle-ci échoue. Par défaut : désactivé. |

Les quatre états :

- **affiché** : l'élément est visible à l'écran.
- **cliquable** : l'élément est visible et peut recevoir un clic ou un tap.
- **activé** : l'élément est actif (pas désactivé).
- **présent** : l'élément existe dans l'arbre UI, même s'il est masqué.

## Résultats et métriques

- **Timing** : début, fin et durée (en secondes). La durée indique combien de temps la condition a mis à devenir vraie, un signal utile en soi.
- **Statut** : succès dès que la condition est remplie, échec si le temps d'attente expire.
- **Capture d'écran** : prise pour l'état vérifié.
