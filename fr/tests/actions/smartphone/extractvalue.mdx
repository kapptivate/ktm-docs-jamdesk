---

Utilisez-la pour un numéro de commande à vérifier, un prix à comparer, un identifiant généré à saisir dans un autre formulaire. L'étape lit le texte de l'élément (ou sa valeur, pour les champs de formulaire) et le stocke dans une variable.

## Paramètres

| Paramètre | Requis | Description |
| ----------- | -------- | ------------- |
| Élément ciblé | Oui, sauf si un sélecteur manuel est défini | Description en langage naturel de l'élément à lire. |
| Sélecteur manuel | Non | Sélecteur XPath ou CSS, utilisé lorsque l'IA est désactivée ou comme sélecteur enregistré. |
| Variable | Oui | Nom de la variable qui reçoit la valeur extraite. Par défaut : `Extracted`. |
| Utilisation de l'IA | Non | `inherit` (par défaut, suit la stratégie du test), `smart` ou `always`. |
| Ignorer les erreurs sur cette étape | Non | L'exécution continue avec l'étape suivante si celle-ci échoue. Par défaut : désactivé. |

## Résultats et métriques

- **Variable** : le contenu textuel de l'élément (ou sa valeur, pour les champs de formulaire) est stocké dans la variable et disponible pour toutes les étapes suivantes. Insérez-la partout où un champ supporte les variables.
- **Timing** : début, fin et durée (en secondes) enregistrés dans le résultat de l'étape.
- **Statut** : succès, avertissement ou échec, avec le message d'erreur en cas d'échec.
- **Capture d'écran** : prise après l'exécution de l'étape.
- **Utilisation de l'IA** : si l'IA a localisé l'élément, le sélecteur corrigé est enregistré sur le test et le coût IA est ajouté à l'exécution.

Consultez [Variables](/fr/tests/variables) pour savoir comment les valeurs extraites peuvent être réutilisées entre les étapes.
