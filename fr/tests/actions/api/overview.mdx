Ajoutez un step API quand un test doit appeler un service directement, sans passer par l'écran. Vous l'ajoutez depuis le [test builder](/fr/tests/builder) comme tout autre step. Il se comporte de la même façon dans un test web et dans un test mobile, avec les mêmes conditions sur la réponse et les mêmes métriques de temps : seul le test qui l'entoure change.

## Actions API

Les actions API HTTP sont disponibles dans les tests existants :

- **Dans un test web** : ajoutez des requêtes HTTP aux côtés des steps navigateur. Identifiant d'action : `ETH_HTTP_API`.
- **Dans un test mobile** : ajoutez des requêtes HTTP aux côtés des steps smartphone. Identifiant d'action : `DATA_API_HTTP`.

Les deux partagent la même configuration de requête et le même modèle d'assertion sur les réponses, avec quelques différences de routage spécifiques au canal.

Dans un test **Web (New experience)**, il s'agit du [step API Call](/fr/tests/actions/web/apicall) : la même requête, plus des conditions sur la réponse dans l'onglet Checks du step et une visualisation de la réponse dans le builder comme dans les résultats. Les tests classiques, le [CLI](/fr/cli/guides/create-tests) et le MCP le désignent toujours par son identifiant, `ETH_HTTP_API`.

## Configuration de la requête

- **Méthodes HTTP** : `GET`, `POST`, `PUT`, `PATCH`, `DELETE`.
- **URL**, qui peut contenir des variables.
- **Headers personnalisés** avec autocomplétion pour les headers standards.
- **Corps** : payload JSON ou brut.
- **Routage** : remplacement DNS, proxy, contournement SSL, conservation des cookies, gestion des redirections.

## Validation de la réponse

- Vérification du **code de statut**.
- Assertions sur le **corps** et les **headers**.
- **Extraction de variables** depuis la réponse pour utilisation dans les steps suivants.

## Métriques par requête

Chaque requête HTTP enregistre la durée de chaque phase : résolution DNS, connexion TCP, handshake TLS, génération du contenu, transfert et total. Servez-vous-en pour repérer un service qui ralentit, pas seulement un service qui échoue.
